## 1. 제품 정의

플레이어의 캐릭터가 **체스말이 되어** 보드 위에서 싸우는 **PvE 우선 로그라이크**.

핵심 구조 한 줄: **보유한 체스말 = 목숨. 어느 말로 싸울지는 내가 못 고른다.**

- 런 시작 시 보유 말 중 **하나가 랜덤 배정**됨 (플레이어 선택 불가)
- 그 말 **1기**로 싸움
- 죽으면 → **남은 보유 말 중 또 랜덤** 배정 → 런 계속
- 보유 말을 전부 소진하면 런 종료
- 플레이로 번 재화로 말을 사면 → **목숨이 늘고 런이 깊어짐**

말들은 **강약이 아니라 스타일 차이**(사이드그레이드)입니다. 가격은 파워가 아니라 **해금 순서·난이도**를 뜻합니다.

## 4. 확정 결정

| 항목 | 결정 |
|---|---|
| 장르 | PvE 우선 로그라이크, 플레이어 = 체스말 |
| **판당 유닛 수** | **1기** (배정된 말 하나로 싸움) |
| **플레이어 조작** | **턴제 이동 선택** — 내 말의 체스 이동 규칙대로 갈 칸을 직접 고름. 전투는 자동 해결 |
| **난이도 곡선** | **레벨마다 보드가 커지고 적 말이 늘어남** (레벨1 → 레벨2 → … 판 크기 +1) |

| 수익화 | **코스메틱 전용** (공격 모션·색상·스킨) |

| MVP 시퀀싱 | **수익화 없이 리텐션 먼저 검증** |
| 타겟 지역 | **글로벌, 영어 우선** |
| 폴더 | `01_Chess/` 단독, `00_VS` 미접촉 |

### 4.1 "말 = 목숨"이 해결한 것

초기 설계 검토에서 지적된 모순: *가격 사다리 + 랜덤 배정 = 비싼 말을 살수록 체감 손해*(6개 보유 시 킹을 6번에 1번만 플레이, 폰은 버릴 수 없는 부채).

**목숨 구조가 이를 제거합니다.** 말 구매는 추첨 확률 희석이 아니라 **목숨 추가**이므로 언제나 명확한 이득이고, 폰도 부채가 아니라 여분 목숨입니다. 부수 효과로 **말이 죽을 때마다 플레이스타일이 강제로 바뀌어** 한 런 안에서 변주가 생깁니다.

### 4.2 코스메틱 전용 결정의 근거

- **Tower Defense Simulator**: 코스메틱 크레이트 중심으로 **7년 · 48.6억 방문 · CCU 21,357 안정**. 45개 세트에서 **붕괴도 급등도 안 한 유일한 타이틀**.
- **규제 리서치**: `random power + 미성년자 + 루트박스` = 최대 노출 조합.
- **플레이어=체스말**이라 모든 코스메틱이 상시 노출 → 코스메틱 수익화 전제 충족.

**트레이드오프**: ARPDAU 상한이 낮음. **"12~18개월 스파이크 후 사망" 대신 "느리지만 durable"**을 선택.

## 5. 코어 게임 루프

```
런 시작 → [랜덤 배정 → (리롤 1회) → 전투 → 사망] × 보유 말 수 → 런 종료 → 재화 획득 → 말 구매
```

### 5.1 런 내부 (In-run)

| 단계 | 내용 |
|---|---|
| **배정** | 보유 말 중 **1개 랜덤**. 플레이어 선택 불가. **리롤 1회** 가능 |
| **턴** | 플레이어가 **내 말의 이동 규칙대로 갈 칸을 선택** → 이동 → **전투 자동 해결**(도착·인접 시) → 적 턴 |
| **레벨 클리어** | 해당 레벨의 적 말 전멸 시 다음 레벨 |
| **레벨 상승** | **보드가 한 칸씩 커지고 적 말 수·난이도 증가** |
| **사망** | 남은 보유 말에서 **또 랜덤 배정** → 이어서 진행 (도달 레벨 유지) |
| **런 종료** | 보유 말 전부 소진 |
| **정산** | 도달 레벨 기준 경험치·재화 지급 |

**난이도 곡선 예시** (§12-1에서 시작 크기 확정 필요):

| 레벨 | 보드 | 적 말 |
|---|---|---|
| 1 | N×N | 소수 |
| 2 | (N+1)×(N+1) | 증가 |
| 3 | (N+2)×(N+2) | 증가 |

보드가 커지는 것은 단순히 넓어지는 게 아니라 **기물별 유불리를 바꿉니다** (§5.3). 초반 작은 판은 근접형(King·Pawn)에 유리하고, 후반 넓은 판은 원거리형(Rook·Bishop·Queen)에 유리합니다. 이게 "말이 죽어 다른 말로 바뀔 때 체감이 달라지는" 변주의 핵심 동력입니다.

### 5.2 메타 (Between runs)

| 단계 | 내용 |
|---|---|
| **재화 획득** | 런 성과에 비례 |
| **말 구매** | 폰(최저가) → 킹(최고가). **게임 내 재화만** |
| **효과** | 보유 말 +1 = **목숨 +1 = 런이 더 깊어짐** + 스타일 변주 증가 |

### 5.3 기물별 플레이스타일 (사이드그레이드)

체스 기물의 **이동 규칙을 전투 문법으로 전환**. 강약이 아니라 **다른 문제 풀이 방식**입니다.

| 기물 | 스타일 | 전투 문법 |
|---|---|---|
| Pawn | 근접·정직 | 전방 인접. 조건 충족 시 승격 (런 내 성장형) |
| Knight | 도약·기습 | L자 이동으로 전열 무시, 후방 접근. 직선 차단에 강함 |
| Bishop | 사선·관통 | 대각선 라인. 각을 만드는 배치 요구 |
| Rook | 직선·압박 | 직선 라인 관통. 정렬로 광역 처리 |
| Queen | 전방위·고난도 | 전 방향. 강력하나 판단 실수 비용도 큼 |
| King | 저사거리·생존 | 인접 1칸만. 대신 생존·회복 특화. **가장 어려운 말** |

> **King이 가장 비싼 이유는 강해서가 아니라 가장 어렵기 때문**입니다. 가격 = 숙련도 게이트.

#### 보드 크기별 기동성 (계산값, 빈 판 기준)

| 보드 | Knight | Bishop | Rook | Queen | King |
|---|---:|---:|---:|---:|---:|
| **3×3** | **1.8 (최소 0)** | 2.2 | 4.0 | 6.2 | 4.4 |
| 4×4 | 3.0 (최소 2) | 3.5 | 6.0 | 9.5 | 5.2 |
| 5×5 | 3.8 (최소 2) | 4.8 | 8.0 | 12.8 | 5.8 |
| 6×6 | 4.4 (최소 2) | 6.1 | 10.0 | 16.1 | 6.1 |

두 가지 사실이 나옵니다.

1. **3×3에서 Knight는 깨집니다.** 중앙에 선 Knight의 합법 이동은 **0개** — L자 이동이 전부 판 밖입니다. 소프트락 상태. **4×4부터 최소 2로 회복**됩니다. → §12-1
2. **기동성 격차는 판이 커져도 안 줄어듭니다.** Queen:Knight 비율이 3×3에서 3.4배, 6×6에서도 3.7배로 유지됩니다. 따라서 **"사이드그레이드"는 기동성으로 맞출 수 없고 보정 능력치로 설계해야 합니다** — 예: Queen은 기동성이 높은 대신 내구가 낮고 우선 표적이 됨, Knight는 기동성이 낮은 대신 **차단 무시**(다른 말을 뛰어넘음)와 순간 화력을 가짐. 이 보정 설계가 밸런싱 작업의 본체입니다.

### 5.4 플레이어 행위 주체성 — 해결됨

**턴제 이동 선택으로 확정.** 플레이어는 매 턴 자기 말의 체스 이동 규칙 안에서 **갈 칸을 고르고**, 전투는 자동 해결됩니다.

이 결정이 기획 전체를 지탱합니다:
- **"보드 위 판단이 실력"** 근거가 성립합니다. 이동 선택이 곧 의사결정 표면.
- **기물 정체성이 실제로 중요해집니다.** Knight의 선택지와 Rook의 선택지는 완전히 다른 퍼즐이므로, 말이 바뀌면 게임이 바뀝니다 — "말 = 목숨" 구조의 변주가 여기서 나옵니다.
- **턴제라 서버 권위 구현이 저렴합니다.** 실시간 위치 검증이 불필요하고, 합법 이동 검증만 서버에서 하면 됩니다.

남은 하위 이슈는 **시작 보드 크기**입니다 (§12-1) — 3×3은 Knight를 소프트락시킵니다.

## 6. 리텐션 설계 (v1 이후)

1. **컬렉션 = 목숨 (본 게임 고유의 최강 훅)**
   일반적인 수집 게임은 "다 모으면 끝"이지만, 여기서는 수집이 **런 깊이**로 직결되고 각 말이 **다른 플레이 경험**을 줍니다. 벤치마크가 지목한 붕괴 원인("컬렉션 완성 = 이탈")에 대한 구조적 방어.
   근거: Pet Simulator 99 "2,000+ 펫" CCU 163,141, Sol's RNG "400+ 오라" CCU 31,010 — 분모가 보이는 수집 카운터의 위력.
   적용: dex UI를 v1에 탑재. `6 기물 × N 스킨 × 레어도`.

2. **시즌제 Elo 래더 + 하드 리셋 + 랭크 전용 코스메틱**
   근거: Blade Ball(시즌마다 Elo 전원 초기화 + 랭크 게이트 스킨, CCU 13,344), RIVALS(시즌 2~3개월, CCU 202,868).
   적용: **8주 시즌, Elo 전체 리셋, 티어별 시즌 한정 스킨 1종.**

   ✅ **랭크 공정성 — 정규화 공용 풀 확정.** 유료 P2W가 없어도 로스터를 다 모은 고인물은 **목숨 수**에서 우위를 가지므로, 보유 로스터로 랭크를 치르면 Elo가 *배치 실력*이 아니라 *투자 시간*을 측정하게 됩니다. 랭크는 **전원 전체 로스터로 입장**합니다. 수집(dex)은 PvE·코스메틱 축, 랭크는 순수 실력 축으로 완전 분리.

3. **재방문율 최적화 (`top-revisited`)**
   근거: The Battle Bricks(CCU 7,420)가 Roblox 자체 `top-revisited` 정렬에 노출 — 알고리즘 무료 배포.
   적용: CCU 스파이크가 아닌 **D1/D7 복귀율**을 최적화 대상으로.

4. **일일 로그인 — 직접 만들지 말 것**
   근거: Roblox 1차 제공 **Engagement Rewards 기능 패키지**(클라·서버 로직 + UI + Daily/Time 타입 + 스트릭 리셋).
   적용: 패키지 투입, 엔지니어링 0. 노력은 **보상 내용물**에만.

5. **트레이드 — 보류**
   유료 가챠 + 트레이드 = 미성년 대상 환금성 루트박스 구조. 출시 시 **코스메틱 한정 + 유료 뽑기 획득물 영구 거래 불가**. v2 이후 검토.

## 7. 수익화 설계 (v1)

**템플릿: Tower Defense Simulator** (코스메틱 크레이트로 7년 생존).

### 7.1 SKU 구조

Roblox 결제 수단 선택 규칙:
- **Game Pass** = 1회성 영구 해금 (소유 중복 자동 처리). 매출 비중 약 55%.
- **Developer Product** = 반복 구매. 매출 비중 약 30%.

| SKU | 유형 | 내용 |
|---|---|---|
| 공격 모션 스킨 크레이트 | Dev Product | **공격 모션만 변경**. Basic(게임 재화) / Premium·Deluxe(Robux) |
| 색상 커스텀 | Game Pass | **유료 전용** 색상 팔레트 |
| 장식 무기 | Game Pass / Dev Product | 외형 전용, 전투력 0 |
| 보드·VFX·처치 연출 | Dev Product | 두 번째 코스메틱 축 |
| 시즌 패스 | Game Pass | 약 400~800 Robux, 8주 시즌 연동 |
| 럭 / 추가 뽑기 | Dev Product | **확률·횟수 판매** (코스메틱 대상) |
| 이벤트 한정 크레이트 | Dev Product | 재출시 없음 (FOMO) |

가격: 진입 25~99 Robux → 프리미엄 1,000+ Robux, **4~6단 티어**, 중·상위에 "best value" 앵커.

### 7.2 절대 금지선

- **체스말을 현금으로 판매 금지.** 말 = 목숨이므로 이는 곧 목숨 판매 = P2W.
- **🔴 게임 내 재화를 현금으로 판매 금지.** 재화로 말을 사므로, **재화 판매 = 우회적 목숨 판매**입니다. 코스메틱 전용 원칙을 무너뜨리는 가장 흔한 뒷문이므로 명시 차단.
- 목숨·부활·컨티뉴를 유료로 판매 금지.
- 랭크 매치에 유료 요소 유입 금지 (**출시 제약이지 v2 수정사항 아님**).
- Robux → 거래 가능 가치 경로 생성 금지.

## 8. 컴플라이언스 — 필수 엔지니어링 (협상 불가)

> **코스메틱 가챠도 규제 면제가 아닙니다.** Roblox "Paid Random Items" 정책은 Robux(및 Robux 파생 재화)로 구매하는 **모든** 무작위 아이템에 적용됩니다.

| 요구사항 | 구현 |
|---|---|
| 확률 공시 | 모든 결과 + **실제 수치 확률, 합계 정확히 100%**, **구매 전** 노출 |
| 정책 API | `PolicyService:GetPolicyInfoForPlayerAsync()` **호출 필수** |
| 지역 제한 | `ArePaidRandomItemsRestricted` 준수 → **비무작위 대체 경로 필수** |
| 거래 제한 | `IsPaidItemTradingAllowed` 준수 |
| 미준수 결과 | **해당 지역에서 게임 자동 이용불가** |

**현재 차단 지역**: 영국 18세 미만, **호주 전체 유저**. 확대 추세.

**한국**: 게임산업진흥법 법률 제19242호(2024-03-22 시행). **간접 구매**(Robux로 산 게임 내 재화)까지 포함. 위반 시 최대 징역 2년 / 벌금 2,000만원. 연평균 매출 1억원 이하 소규모 사업자 면제.

**설계 반영**: 확률 테이블을 **데이터로 정의**하고 클라이언트 렌더, **배너별 버전 관리**. 비무작위 경로(색상·장식 직접 구매)를 차단 지역 대응 경로로 승격. `[Medium]` 출시 전 법률 검토 필요 — 본 문서는 법률 자문이 아님.

**주의**: 런 시작 시 **말 랜덤 배정은 유료 무작위가 아닙니다** (게임플레이 장치, 결제 무관). Paid Random Items 정책 대상은 코스메틱 크레이트뿐입니다. 이 구분을 구현·심사 시 명확히 유지할 것.

## 9. 기술 아키텍처

`00_VS`의 코드를 복사하지 않고, **동일 스택·패턴으로 `01_Chess/`에 신규 스캐폴딩**합니다.

### 9.1 스택
- **rokit** 툴체인 핀: rojo 7.7.0 / lune 0.10.5 / selene 0.31.0 / stylua 2.5.2
- Rojo 소스 트리 → `.rbxlx` 빌드
- Lune 기반 **dual-runtime 테스트**

### 9.2 원칙
- **서버 권위**: 전투 판정·보상·재화·구매·랜덤 배정 전부 서버 소유. 클라이언트 결과 불신.
- **랜덤 배정은 반드시 서버에서.** 클라이언트가 배정을 굴리면 원하는 말이 나올 때까지 재시도하는 치트가 성립합니다. 리롤 횟수도 서버 상태.
- **순수 결정론 Rules 모듈**: Roblox 인스턴스 의존 0 → 단위 테스트 가능.
- **RemoteEvent 토큰 검증**: 클라이언트는 서버 발급 토큰 + 선택지 ID만 제출.
- **속성 기반 리플리케이션**: 권위 상태는 서버 전용.
- **DataStore**: 보유 말·재화·진행도·dex·Elo·코스메틱 소유권 영속화.
- **MarketplaceService**: 게임패스/개발자상품 + 영수증 검증.

### 9.3 결정론의 부수 효과
전투가 완전 결정론이면 `(초기 상태 + 시드)`로 재현 가능 → 리플레이 공유(바이럴) · 서버 검증(안티치트) · 재현 가능한 밸런스 테스트가 **하나의 설계**에서 나옵니다.

## 10. 범위 (Scope)

### MVP (리텐션 검증 전용)
- 런 루프 (§5.1) + 메타 재화·말 구매 (§5.2)
- **턴제 이동 선택 + 자동 전투 해결** (핵심 검증 대상)
- **레벨별 보드 확대 + 적 증가** 난이도 곡선
- **기물 3종으로 시작** (예: Pawn / Knight / Rook) — 이동 문법이 서로 가장 다른 조합. 사이드그레이드 검증에 3종이면 충분. 6종 전체는 v1
- 랜덤 배정 + 리롤 1회 (서버 권위)
- 목숨 소진 → 런 종료 → 정산 → 재구매
- dex 카운터
- 계측 3종
- **수익화 없음. PvP 없음. 시즌 없음.**

### v1 (MVP 통과 시)
- 기물 6종 완성
- 코스메틱 수익화 전체 (§7) + 컴플라이언스 (§8)
- Engagement Rewards 일일보상
- 시즌제 Elo 래더 (§6-2)

### v2 이후
- PvP (실시간 또는 비동기)
- 제한적 트레이드 (코스메틱 한정)
- 이벤트 캘린더

### 명시적 비목표
- 정통 체스 룰 재현
- 전투력·목숨·재화 판매
- 유닛 가챠
- 무제한 트레이드 시장

## 12. 미결 사항

1. **🔴 시작 보드 크기 (개발 착수 차단)** — 레벨1을 3×3으로 시작하면 **Knight가 중앙에서 합법 이동 0개**가 되어 소프트락됩니다(§5.3 계산값). 랜덤 배정이라 플레이어가 이를 피할 수 없습니다. 선택지: ⓐ **시작을 4×4로** (Knight 최소 이동 2 확보, 가장 단순) ⓑ 3×3 유지하되 저레벨에서 Knight 배정 제외 ⓒ 3×3 유지하되 Knight에 소형 판 전용 보정 이동 부여. **권고: ⓐ.**
2. **영문 정식 제목** — 글로벌·영어 우선이므로 필요. 현재 폴더 작업명 `01_Chess`.
3. **MVP 성공 임계값** — §3.3 수치는 벤치마크 미근거 `[Low]`.
4. **말 가격 곡선** — 폰→킹 가격 배율, 첫 말 지급 여부, 초기 보유 수(= 초기 목숨 수).
5. **출시 전 법률 검토** — `[Medium]` v1(수익화) 착수 시점 필요. MVP에는 불필요(유료 무작위 없음).
